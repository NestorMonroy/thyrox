Patrón: narrow-schema-field-cast-via-record-unknown
Señal del verificador: TS2352:.*may be a mistake because neither type sufficiently overlaps
Arreglo genérico: Cuando un literal de prueba fija un campo con un tipo más estrecho (p. ej. un string) que el tipo real de ese campo en el esquema de producción (p. ej. un objeto `{ type: 'command'; command: string }`), no castear el literal directamente con `as SettingsJson` (o el tipo del esquema que sea). Declarar antes una variable tipada `Record<string, unknown>` con el mismo literal, y castear esa variable — el índice `[x: string]: unknown` del esquema hace la conversión estructuralmente válida sin recurrir a `as unknown as` ni a `any`. Ya es el patrón que el propio archivo usa para `hooks: null` (`nullHooksSettings`).

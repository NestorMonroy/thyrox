# T002 — TASK-THYROX-0769: los bancos registran la búsqueda antes de implementar

Depende de T001 integrado.

## Objetivo

Antes de crear un mecanismo, un banco deja evidencia verificable de que buscó:

    bin/search_existing_mechanisms --bench <banco> <consulta>   (registra la búsqueda)
    -> inspección de autoridad y pruebas
    -> git grep adversarial
    -> decisión REUSE | EXTEND | MISSING

## Archivos que te pertenecen (y ningún otro)

`src/workbench/manifest.py`, `tests/workbench/test_manifest.py`, `src/verify/check_mechanism_search_evidence.py`,
`tests/verify/test_check_mechanism_search_evidence.py`, `src/verify/registry.py`,
`bin/check_mechanism_search_evidence` (generado), y `outputs/T002-*` de este banco.

## Mecanismos que DEBES reutilizar

`bin/search_existing_mechanisms` y su `outputs/mechanism-search.jsonl` (T001); `src/verify/registry.py`;
la plantilla de README que ya escribe `bin/manifest scaffold`.

## Lo que se construye

1. `bin/manifest scaffold` añade al README la sección «Búsqueda de mecanismos existentes»: una tabla
   `consulta | resultado | autoridades inspeccionadas | decisión | evidencia`.
2. `bin/check_mechanism_search_evidence BANCO`: cada fila de esa tabla tiene que corresponder a una
   línea de `BANCO/outputs/mechanism-search.jsonl` con la misma consulta y el mismo resultado; una
   decisión MISSING exige además una línea `{"kind":"adversarial","query":...,"command":...,"matches":N}`
   en el mismo archivo (que el banco escribe al correr su `git grep`). Una fila sin evidencia falla; una
   tabla vacía en un banco que añade archivos bajo `src/` falla. Sale 0/1/2 como el resto de gates, y se
   registra en `src/verify/registry.py`.

## RED / GREEN / Anulación / Evidencia

Como T001: pruebas nuevas que fallan contra la base; GREEN con sus pruebas, `tests/verify/test_runner.py`
y `bin/generate_bin --check`; anulación con un banco de prueba cuya fila no tiene línea en el jsonl, y
otro con MISSING sin línea adversarial: cada uno falla y nombra la fila. Evidencia en `outputs/T002-*`.
